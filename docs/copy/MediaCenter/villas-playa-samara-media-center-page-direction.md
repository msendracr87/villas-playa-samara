# Villas Playa Sámara — Media Center Page Direction

> **Purpose:** Direction for building a dedicated Media Center for Villas Playa Sámara.  
> **Primary audiences:** Travel agents, tour operators, resale partners, media, vendors, designers, marketing partners, and approved collaborators.  
> **Status:** UX/content direction draft.  
> **Goal:** Make approved brand materials easy to find, preview, understand, and download without requiring users to request files manually.

---

# Recommended Page Name

## Primary Recommendation

# Media Center

**Supporting label:** Brand Assets & Resources

This is the clearest public-facing name because it works for both hospitality partners and media users without sounding overly technical.

### Other Good Options

- Brand Resources
- Media & Brand Assets
- Marketing Resources
- Partner Media Library
- Brand & Media Library

For website navigation, **Media Center** is the strongest choice.

---

# Page Purpose

The Media Center should act as the official source for current Villas Playa Sámara marketing and brand materials.

Users should be able to quickly:

- Download approved logos
- Find high-resolution photography
- Access room and villa imagery
- Download restaurant and wellness imagery
- Find resort lifestyle photography
- Access brochures and sales materials
- Review basic brand-use guidance
- Download grouped asset packages
- Confirm which files are current
- Know whom to contact for additional material or usage questions

The page should reduce back-and-forth between the resort and external partners while helping prevent outdated, low-resolution, or incorrectly used assets from circulating.

# Access Strategy

## Recommended Approach: Public Core Library + Controlled Sensitive Assets

The Media Center should be easy to access for common approved materials.

### Publicly Accessible

Suitable assets may include:

- Logos
- Approved resort photography
- Accommodation photography
- Restaurant photography
- Wellness photography
- Destination photography
- Property fact sheet
- Approved resort descriptions
- Public brochures
- Social-media-safe assets

### Optional Restricted Access

Consider password protection, partner login, or request-based access for:

- High-value campaign files
- Original editable design files
- Raw photography
- Unreleased development imagery
- Rate sheets
- Sales presentations
- Contract materials
- Internal templates
- Assets with usage limitations

The public page should never expose internal working files simply because they exist in the same storage library.

# Photography Organization

Avoid presenting photography as one enormous gallery.

Organize images by subject and use consistent naming.

## Resort Photography

Suggested groups:

- Property Overview
- Beachfront
- Pools
- Lobby & Arrival
- Gardens & Grounds
- Lifestyle

## Rooms & Villas

Create one subsection per category.

For example:

### Junior Suite Garden View

- Bedroom
- Living area
- Kitchen
- Bathroom
- Terrace
- Garden setting

Repeat this structure for each accommodation category.

This makes the library significantly more useful to travel agents and resale partners because they can identify exactly which room category an image represents.

---

# Image Accuracy Rule

This is especially important for hospitality resale.

Every image should be attached to an accurate category.

Do not label a generic bedroom photograph simply as:

**Room**

Prefer:

**Junior Suite Garden View — Bedroom**

or:

**Two Bedroom Beachfront Villa — Living Area**

This reduces the risk of partners using the wrong imagery for an accommodation category.

---

# Development & Concept Imagery

Future developments should be visually separated from completed facilities.

Examples include:

- Morpho Wellness Retreat expansion
- Yoga deck
- Children's recreation area
- Future restaurant or architectural concepts

Use a visible status:

**Conceptual Rendering**

or:

**Future Development — Concept Image**

Recommended note:

> This image represents a development concept. Final architecture, finishes, landscaping, furnishings, and services may vary.

Do not mix renderings into a completed-property gallery without this distinction.

# Logo Usage Guidance

Include a compact guideline rather than requiring every user to open a large brand manual.

## Please

- Use official logo files provided here
- Maintain the original proportions
- Leave sufficient clear space around the logo
- Choose the version that provides adequate contrast

## Please Avoid

- Stretching or compressing the logo
- Recoloring the logo outside approved colors
- Adding shadows, outlines, or effects
- Recreating the logo with a different font
- Cropping or modifying the mark
- Placing the logo over a background with poor contrast

**CTA:** View Brand Guidelines

# Download Behavior

## Individual Assets

Each file should have a clear:

**Download**

button.

Do not make users right-click images from the browser.

## Multiple Assets

Allow users to select several assets and choose:

**Download Selected**

The system can create a ZIP file dynamically or provide predefined ZIP packages.

## Download All

Avoid a single unrestricted **Download Everything** button if the library becomes large.

Curated packs are better because they:

- Stay current
- Reduce file size
- Prevent accidental distribution of internal material
- Give users the strongest approved selection

# File Naming Convention

Use consistent filenames.

Recommended pattern:

```text
VPS_Category_Subject_Description_Orientation_001.ext
```

Examples:

```text
VPS_Resort_Beachfront_Aerial_Landscape_001.jpg
VPS_Rooms_JuniorSuiteGarden_Bedroom_Landscape_001.jpg
VPS_Dining_Arrecife_Interior_Landscape_001.jpg
VPS_Wellness_GYM_Cardio_Landscape_001.jpg
VPS_Logo_Primary_Dark.svg
```

Avoid filenames such as:

```text
IMG_4828.jpg
final-final2.png
hotel-new-photo.jpg
logo-good.svg
```

# Recommended Page Design Direction

The page should feel more like a modern asset library than a traditional hotel content page.

## Visual Style

Use:

- Clean grid
- Large thumbnails
- Generous white space
- Minimal decorative elements
- Short labels
- Consistent card dimensions
- Clear filters
- Visible download actions

Avoid:

- Large paragraphs before users reach the assets
- Decorative animations that slow browsing
- Hiding download buttons behind hover-only interactions
- Forcing users through multiple pages to download one image
- Mixing outdated and current assets

# Storage & Technical Direction

The website should not necessarily store every original file directly inside the application repository.

A better structure is:

```text
Website
   ↓
Asset metadata / library interface
   ↓
Cloud or object storage
   ↓
Downloadable approved files
```

This makes it easier to:

- Replace assets
- Organize large photography libraries
- Serve ZIP packages
- Keep the website repository small
- Track versions
- Add or remove files without a full website rebuild

---

# Strongest Recommendation

Treat the Media Center as an **official distribution library**, not simply a photo gallery.

The key difference is that every asset should answer three questions:

1. **What is this?**
2. **Is this the current approved version?**
3. **How may I use it?**

If those three answers are clear, the page becomes genuinely useful to travel agents, resale partners, media, vendors, and the internal Qviva team.
